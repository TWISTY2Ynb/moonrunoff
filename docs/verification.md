# 验证口径与限制

## 工具链及平台

当前验收基线：moonc v1.0.0-rc1+3c0520448，moon/moonrun 0.1.20261126；最低 moonc 1.0.0-rc1。CI 从官方固定 URL 下载同版本 compiler/core，逐项断言三个工具版本。旧版 0.10.22 的派生语法迁移保持不变；RC1 不再通过已弃用的 JSON 深度参数限制输入，而是在调用标准 JSON 解析器前用常量空间扫描限制容器深度，保留字符串转义、重复键拒绝和 1 Mi 输入上限。Windows 本地实际完成 wasm-gc、wasm、js 的严格 check/build/test 和三个工作流；native check 通过，但本机没有可用 C 编译器，未完成 native build/test。Linux native 以该精确提交的实际 Actions 为准，不声称 Windows native 已通过。

MoonCakes 服务端的构建环境由服务端选择。精确版本的公开构建日志能证明执行了哪些检查、文档及构建任务，但若未输出编译器版本，就不能据此断言服务端使用了上述固定工具链。

## 核心功能路径

- 三角：维度、增量/累计互换、复制隔离、历史截面、日历/发展聚合。
- 因子：Volume/Simple/Regression，窗口、排除、覆盖、零基数、尾因子、溢出。
- 四模型：手算 CL/BF、Benktander 迭代定义、Cape Cod 调整暴露量。
- 输出：逐事故期准备金、支付日历、尾支付、完整累计投影、组合重述、贴现和会计/现金流对账。
- 复核：逐配对残差、描述统计、截面重新拟合的历史留出、压力比较。
- 入口：严格 JSON/CSV、全部请求 action/estimator、三个工作流和 CLI。

仓库有 25 个测试块，测试不依赖联网。不同测试块内包含多个边界和数值断言，不能把测试块数等同独立输入数。

## 独立预期

`tools/differential.py` 使用 Python 标准库 Fraction，以固定种子 20261109 生成 12 个 2–9 阶正整数三角。独立公式生成三种发展因子的 CDF 和四种模型的最终赔款，包含尾因子 1.1、Benktander 三次迭代及 Cape Cod 暴露量。通过实际 CLI 发起 144 个请求，逐事故期比较 780 项结果；本地最大相对误差 8.125828050905859e-16，容许阈值 1e-10。每请求另外核对支付总额等于准备金。没有使用上游夹具。

手算样本 [[100,150,180],[120,180],[140]]：因子 [1.5,1.2]，CL 最终赔款 [180,216,252]，准备金 [0,36,112]。留出测试替换未来观测而保持相同预测，检查无未来泄漏。

## 成熟参考库对照

`tools/reference_chainladder.py` 在独立 Python 3.12 环境使用 chainladder 0.8.24；`tools/reference-requirements.txt` 固定直接兼容依赖。最初最新 sparse 的内部接口与该版本不兼容，固定 sparse 0.17.0 后实际运行成功，未修改参考库源代码。复现命令：`python -m pip install -r tools/reference-requirements.txt`，再执行 `python tools/reference_chainladder.py`（MoonBit 在 PATH）。

固定种子 20261111，6 个自生成年度三角，三种拟合和四模型，共 72 个 CLI 请求、348 项事故期最终赔款比较；最大相对误差 6.96240583614938e-16，阈值 1e-10。明确仅比较正值年度三角、tail=1、无配对排除、无趋势的共同语义；尾因子由上节 Fraction 独立测试验证。没有复制参考库的源码、注释、数据或测试夹具。此可选测试不增加 MoonBit 模块运行依赖。

## 覆盖率

执行 `moon coverage clean`、`moon test --enable-coverage --deny-warn`、`moon coverage report -- -f summary`。RC1 本地实测为 664/782 个工具报告覆盖点，包含未作为单元测试执行的示例/CLI 入口，不把该值当行覆盖率或分支覆盖率；工具摘要未列出的文件也不能从此推定为零覆盖或全覆盖。更换编译器或源文件后若残留旧 trace metadata，先执行 `moon clean` 再运行覆盖率测试；不要混用不兼容的 trace。CI 从干净 checkout 重新生成当前提交的摘要。覆盖率仅辅助，不替代独立预期和完整工作流执行。

## 源码量及历史口径

只计根目录实际生产 `.mbt`，排除 `_test.mbt`、`_wbtest.mbt`、生成接口、示例、薄 CLI、Python 工具、配置和文档；计物理行并另外列非空非注释行。0.1.0 发布前实测 1817 物理行，1580 非空非注释行；0.1.1 派生语法迁移后为 1828 物理行，1591 非空非注释行；0.1.3 的必要 JSON 深度扫描后为 1853 物理行、1614 非空非注释行，无填充。发布验收报告提供逐文件清单和实际提交摘要。

历史按独立工程切片检查，原始数量与保守有效数量分开。初始 CLI 示例严格 Double 相等断言曾失败，后续改为容差断言；历史保留，保守计数不认领该失败切片为独立已验证成果。不会重写历史或通过空提交补数量。

## 结论边界

查重是有界检索，不保证全球唯一；自检、CI 和安装验证均不是官方验收通过。没有性能排名、Mack 标准误、bootstrap、监管准确性或金融建议的声明。全部客户数据均由调用者负责，本项目测试数据为自生成。

## 0.1.1 工具链回归

`python -m unittest discover -s tools -p 'test_*.py'` 与同命令的 `python -O` 模式均检查最低版本边界、无效输出、缺失/失败编译器与成功路径。版本判断使用显式失败返回，不依赖可关闭的 Python 断言。生产 MoonBit 数值 API 未改变；四后端严格检查、构建、测试及全部示例由当前发布提交的 CI 复验。Windows 本地 native 未完成（系统缺 C 编译器，bundled TCC 亦无法编译该工具链 runtime），不据此声称 Windows native 已通过。

## 0.1.3 RC1 回归

版本门禁使用明确的 alpha < beta < rc < 正式版顺序，覆盖 RC1/RC2/正式版、旧 0.x、alpha/beta、rc0、畸形前导零、未知后缀与缺失编译器；普通和 `python -O` 的 5 个测试方法均通过（各方法含多组边界）。新增 JSON 回归验证 16 层允许、17 层拒绝、字符串内括号/转义不影响计数、重复键与畸形语法拒绝、恰好 1 Mi 输入允许和超限拒绝。25 个 MoonBit 测试块在 wasm-gc/wasm/js 本地均通过；独立 Fraction 144 请求/780 比较与 chainladder 0.8.24 的 72 请求/348 比较均通过。公开 API 没有变更。
